# Horizon 本地 Web 控制台技术方案

采用 FastAPI 适配现有 `HorizonPipelineService`，以 React + TypeScript + Tailwind 构建中文操作界面。运行记录与摘要继续使用 JSON/Markdown 文件，不引入数据库。CLI 只增加共享运行锁接入，避免并发写配置和运行冲突。

- 方案状态：`IMPLEMENTED`，用户完整本地开发委托所批准的适配器与界面已落地。此状态不代表真实模型或个人微信账户已验收。
- 适用 Release：`web-console-local-v1`。
- 需求：[PRD.md](PRD.md)；视觉系统：[根 DESIGN.md](../../DESIGN.md)；接口：[API.md](API.md)。
- 本文根据当前源码维护架构事实；实际执行、浏览器结果及验证限制统一见 [PROGRESS.md](PROGRESS.md)、[VERIFICATION.md](VERIFICATION.md)，不在本文复制通过状态。

## 1. 已核验现状与目标

| 现状 | 依据 | 设计含义 |
|---|---|---|
| MCP 服务已有运行列表、阶段读写、评分、筛选、补充、摘要与配置读取能力 | `src/mcp/service.py`、`src/mcp/run_store.py` | Web 复用服务，避免重写业务流水线 |
| MCP 默认工件目录是 `data/mcp-runs` | `src/mcp/service.py::_default_runs_root` | 与现有格式兼容；不按附件中的 `data/runs` 假设建第二套存储 |
| CLI 直接调用 `HorizonOrchestrator.run`，不保存完整阶段工件 | `src/main.py::main`、`src/orchestrator.py::run` | 旧 CLI 历史不能伪造成可追踪运行 |
| Token 计数是进程内存状态；CLI 只在终端打印 | `src/ai/tokens.py`、`src/orchestrator.py` | Web 在每次任务边界记录快照；历史缺失显示未记录 |
| 接入前 `filelock` 仅保护 ChatGPT 凭据操作；当前已增加流水线数据锁 | `src/ai/chatgpt_auth.py`、`src/run_lock.py`、`src/main.py` | CLI 与 Web 通过数据目录内 `.horizon-run.lock` 互斥 |
| 摘要位于 `data/summaries/horizon-日期-语言.md`，微信会话为本地 JSON | `src/storage/manager.py`、`src/services/wechat.py` | 直接适配已有文件，状态返回脱敏摘要 |

目标覆盖 PRD 的六个用户闭环。外部调度、通知发送、公开网络部署和源市场不在本方案内。

## 2. 技术栈与工程边界

| 使用位置 | 采用技术 | 来源与理由 |
|---|---|---|
| 后端 | Python >=3.11、FastAPI、Uvicorn、Pydantic 2 | Python 基线来自 `pyproject.toml`；Web 框架按用户指定新增，实际锁定版本见 `uv.lock` |
| 前端 | React、TypeScript、Vite、Tailwind CSS 4 | 用户指定 React/Tailwind；类型及构建配置在 `web/`，实际版本见 `web/package-lock.json` |
| 存储与并发 | JSON、Markdown、原子文件写、filelock | 复用现有存储风格与依赖，适合单机个人使用 |
| 运行 | `127.0.0.1:8765` 单端口 | FastAPI 托管 `web/dist`，开发时可单独使用 Vite |

工程规范以 [AGENTS.md](../../AGENTS.md) 为准。`src/web/` 可依赖 `src/mcp/`、模型、存储和微信服务；既有业务模块不反向依赖 Web。`web/` 只通过 `/api` 访问后端，不直接接触配置和会话文件。

## 3. 组件与核心数据流

| 组件 | 职责 | 源码与关键边界 |
|---|---|---|
| FastAPI 入口 | 输入校验、Host/Origin 保护、错误转换、静态资源 | `src/web/api.py`、`server.py`；本地请求与文件系统的边界 |
| 观测读取适配 | 运行/阶段/摘要/配置/微信摘要读取 | `api.py`、`runtime.py`；缺失数据保持未知 |
| 后台任务管理 | 唯一活跃任务、阶段执行、取消、日志与指标 | `runtime.py::RunManager`；运行锁覆盖完整任务 |
| 配置适配 | 白名单局部修改、revision、备份、原子写 | `config.py::ConfigStore`；从原始 JSON 修改 |
| 微信适配 | 登录二维码、验证码、会话保存和上下文刷新 | `wechat.py::WeChatManager`；显式操作才访问网络；历史页预览确认后复用 WeChatNotifier 分段推送 |
| React 界面 | 导航、筛选、阅读、表单、实时日志与反馈 | `web/src/`；后端结果是业务事实来源 |

读取路径为浏览器请求 `/api`，后端读取允许的文件和已有服务，转换为脱敏响应。写路径在请求来源和字段校验后，先取得适用互斥保护，再执行操作；错误不得通过原始异常字符串泄露凭据或内部路径。

### 后台运行

1. 校验时间窗及运行参数，取得共享运行锁；冲突返回明确错误。
2. 创建可查询运行记录，后台依次执行抓取、评分、过滤、补充及摘要生成。调用已有阶段服务，持续保存可用工件。
3. 在任务边界记录开始/结束时间、状态、阶段计数、耗时和 Token；不调用原 CLI 自动通知路径。
4. UI 查询运行详情，通过 SSE 接收日志；断线后可重新读取已保留日志与最新状态。
5. 完成、失败或取消都经过清理路径释放锁。已写工件保留，取消不删除历史、不撤销已发出的外部请求。

任务状态由 `RunManager` 写入；前端不推定成功。完成与取消竞态以任务最终状态为准。启动时无其他进程持锁才将遗留 `web_managed/running` 记录改为 `interrupted`。`shutdown()` 取消本进程活跃任务，保留已写工件。

## 4. 数据与接口契约

| 数据 | 约束及用途 | 写入方 |
|---|---|---|
| 运行标识 | 服务端生成或沿用 RunStore 合法标识，不接受路径穿越 | 后台任务、既有 RunStore |
| `meta.json` | 兼容既有阶段元信息，新增状态、时间、耗时及 Token 字段；缺失字段允许为空 | 任务管理与阶段服务 |
| 四阶段 JSON | 沿用 `raw/scored/filtered/enriched_items.json` 和现有 ContentItem 序列化 | 阶段服务 |
| 运行摘要与历史速递 | 运行内 `summary-语言.md`，已发布本地摘要沿用 `horizon-日期-语言.md` | 现有摘要/存储服务 |
| 原始配置与 revision | revision 对应读取的文件版本；保存时再次核对，白名单 patch 合并原始 JSON | Web 配置适配 |
| 微信登录状态 | 浏览器只见登录任务标识、二维码和阶段摘要；令牌留在服务端 | 微信适配 |

不做数据库迁移和索引。旧工件兼容读取，缺失状态或指标按已知事实显示；不能通过目录更新时间推算精确运行耗时。配置备份使用独立文件，恢复由用户选择正确备份，不覆盖已有 `data/config.json.bak`。

API 接入原则、端点和调用示例见 [API.md](API.md)，字段契约源为 `/api/openapi.json` 和后端请求模型；离线目录为 `/api/docs`。阶段接口支持搜索、来源、保留状态、最低评分及分页，非法标识、阶段和字段在边界拒绝。

配置普通对象递归合并；每个提交的源类型整体替换该类型，分类配额和处理配置参数映射整体替换以支持删除。隐藏凭据和环境变量引用先按已有条目身份恢复，避免正常删除或重排时将脱敏值写回；同一可识别条目保留原有 Schema 未识别的用户扩展字段。完整语义由 `ConfigStore.patch` 与 API 文档维护。

## 5. 关键选择、并发与恢复

- **复用分阶段服务**：其持久化和公开接口与观测需求吻合；直接调用 CLI 完整运行会附带通知和 GitHub Pages 文件写入，不适合本次受控 Web 运行。
- **同端口静态托管**：个人启动和同源请求更简单；前端改动需重新构建才能反映到统一入口。
- **文件存储**：不引入迁移和数据库维护成本，接受单机规模与顺序任务边界。
- **共享锁**：CLI、Web 运行、配置保存和微信登录/刷新/推送使用相同数据目录的锁。既有 MCP 直接调用没有接入该互斥，不能与 Web 同时写同一目录。外部直接编辑配置不受锁保护，因此另用 revision 检测覆盖风险。
- **不自动重试写操作**：重复启动可能产生新任务，配置冲突需用户重新加载；读取和日志连接可由界面重试。
- **微信上下文分阶段处理**：扫码确认后不立即宣称可推送，需要首条消息上下文；额度为本地估算，不代表服务端权威额度。

原子写失败必须保留原文件；任务失败保留工件。取消和失败后不能继续执行下游阶段。服务退出需清理本进程活跃任务；进程强制终止后的状态以启动时恢复检查为准。

## 6. 安全、隐私与可观测性

默认仅本机监听，校验允许的 Host；写操作同时要求与 Host 严格同源的 Origin 和 `X-Horizon-Request: 1`，不启用任意跨域。此机制用于限制浏览器跨站误操作，不作为公开网络认证系统。

配置查询保留环境变量引用并脱敏；写操作只允许白名单字段，恢复已匹配条目的隐藏值并拒绝新增凭据。运行读取在 `RunManager.safe_run` 拒绝符号链接目录或工件，不跟随它们读取其他位置。会话、URL 查询凭据、授权头、异常和日志由相关脱敏测试覆盖。Markdown 使用 `react-markdown`，不执行原始 HTML；条目链接限制 HTTP/HTTPS，外链使用安全打开属性。

运行日志供界面和 SSE 读取，`LogBuffer` 负责脱敏及尾部持久化：内存最多 2000 项、单条最多 8000 字符、磁盘约 1 MB。Token 由已有 tracker 按任务边界重置和采集；历史未记录的不补推断。外部调度没有读取或管理承诺，界面明确未接管。
